## 应优先处理的发现

P1 表示影响数值、复现或结论，建议对外强化宣传前修复；P2 表示影响方法有效性、维护或使用体验。下文区分动态复现、静态确认与需要后续实验评估的风险。

### F01 · P1 · KernelSHAP 的 seed 不控制实际采样

位置：`explaintrust/explainers.py:172–178`。动态复现。

代码将 `random_state=seed` 传入 `shap_values`，但本地 SHAP 0.49.1 的 KernelExplainer 使用全局 `np.random.choice/permutation`，没有在该路径消费此参数。相同 API seed 连续调用出现约 0.200 的最大归因差；保存的探针进一步固定并改变外部全局 RNG 状态，验证同一 API seed 仍受其影响。

这直接违背公开的可复现承诺，也会污染跨 seed 稳定性实验。现有“确定性”测试使用低维线性例子和较大采样预算，无法检出真正进入随机采样分支的问题。

建议：按已验证 SHAP 版本封装 RNG 行为，避免并发调用相互干扰；增加高于枚举预算的非线性采样测试。同 seed 应不受无关 RNG 调用影响，也不应污染调用方 RNG 状态。

### F02 · P1 · 非有限归因会得到“零敏感度”

位置：`explaintrust/metrics/sensitivity.py:46–61`、`explaintrust/report.py:119–121`。动态复现。

解释器始终返回 NaN 时，`max(worst, nan)` 保留初始 0，最终返回 0.0，报告会把它解释为良好。`n_perturbations=0` 也没有有效性校验。另一方面，infidelity 用正无穷表示无输出变化基线下的非零误差，但报告将所有非有限值统一视为 `info`，丢失“不可计算”与“明确失败”的区别。

建议：统一输入维度、有限值及预算检查，分别表达 `ok / failed / unavailable / not_applicable`。NaN 不能变成 good；数学上有含义的正无穷不能仅作为缺失值处理。总体结果应同时保留已失败项和缺失项，而不是缺失信息覆盖全部失败原因。

### F03 · P1 · 低维数据的 top-k 比较必然失去区分能力

位置：`explaintrust/metrics/faithfulness.py:165–185`、`explaintrust/report.py:215–234`、`app/streamlit_app.py:84`。动态复现。

App 允许两列数值特征，并设置 `k=min(3,d)`。当 d 为 2 或 3 时，top-k 和 random-k 都移除全部特征；非零效果下比例约为 1（探针为 0.9999999999996666），报告却将 `<=1` 判 bad。完美线性解释也无法通过。现有两特征端到端测试只检查形状和序列化，没有检查结论。

同一边界下 top-k overlap 恒为 1；k=1 时 Spearman 不可定义。建议在 d>1 时选择 k<d，或明确标记该比较不适用；不能用机械截断替代指标适用性检查。比值 >1 也只是本次随机对照的点估计，不应直接写成已证实“不是噪声”。

### F04 · P1 · 切换实例后稳定性统计串用，且评估预算与展示归因不一致

位置：`app/streamlit_app.py:126–139,468–474`。静态确认。

稳定性只针对 `X_explain[:1]` 计算；UI 任意选择 `instance_idx` 后仍把这份 std 传给逐特征可靠性表。实例 1、2 等的 signal-to-noise 因而来自另一个样本。稳定性运行又使用主归因一半的 LIME 样本量（最少 500），评估的是不同预算的解释器。

建议：std 与实例 ID、解释器预算绑定；只有实例 0 有证据时，其他实例显示未计算，或按需重算。主解释与重复解释使用相同配置，并在导出中记录配置与覆盖范围。

### F05 · P1 · class_index=0 在二分类 margin 路径被忽略

位置：`explaintrust/explainers.py:62–67,96–108,165–170`。predictor 部分动态复现。

LogisticRegression 的一维 `decision_function` 无论 class_index 是 0 还是 1 都原样返回。探针确认两者完全相同。线性 SHAP 的二维输出同样没有对类别 0 翻转归因。用户请求负类时仍可能拿到正类解释；目前 App 固定类别 1，因此主要影响公开库 API。

建议：明确支持类别索引和模型类别标签的对应关系；二分类负类 margin、归因及基值一致变号，或在未实现时明确拒绝。增加类别 0/1 的输出及加性一致性测试，禁止静默忽略参数。

### F06 · P1 · 背景基线并未真正对齐

位置：`explaintrust/explainers.py:80–93,160–170`；真实 benchmark 的 BG=200。部分动态复现、部分静态确认。

TreeSHAP 完全忽略传入的 `X_background`，使用自身默认背景语义；LIME 的贡献转换则使用传入背景的均值。即使输出单位相同，也不能假定基线及被解释对象相同。

在线性路径，本地 SHAP 对大背景集的内部采样也会破坏“与完整背景均值公式精确一致”的承诺：500 行、3 特征的线性探针中，两者最大差约 0.353。这发生在 LIME 近似误差之外。

建议：显式记录实际背景样本、masker、TreeSHAP 模式和 expected value；若需要同基线对比，应使用同一实际背景，否则在报告中标注基线不同。不能为了数值接近而无记录地改变 TreeSHAP 方法定义。

### F07 · P1 · 描述性差异被计入总体“不可靠”判定

位置：`explaintrust/report.py:303–405` 与 `experiments/README.md`。内部证据冲突。

校准文档明确承认：分歧指标在其测试场景中无法区分，magnitude disagreement 甚至方向反转。但报告仍将这些指标按统一红黄绿阈值评分，任意两个 bad 就触发 UNRELIABLE。多个相关的分歧指标还能重复贡献红项。子群差异也会计入同一个总体结果，而其本身只说明解释在群体间不同。

建议：把 fidelity、repeatability、cross-method differences、subgroup heterogeneity 分面展示。描述性指标默认不参与可信性否决，除非存在适用场景与校准证据。为决策规则设版本和可配置策略，而不只是开放数值阈值。保留“未检出问题不等于证明正确”的现有措辞。

### F08 · P2 · benchmark 在划分之前拟合预处理

位置：`experiments/real_datasets.py:76–95`、`experiments/benchmark_real_data.py:184–194`。静态确认。

全量数据用于中位数填补、均值/标准差估计及 one-hot 编码后才 train/test split。这不等于使用测试标签训练，但测试集分布已影响训练变换，削弱“留出评估”的隔离。Diabetes 加载还丢弃 patient_nbr，后续随机划分无法约束同一患者跨集合；实际重叠比例本次未测量。Adult 原有 train/test 被合并后重新划分，也应作为实验协议明确说明。

建议：先保留原始数据和分组标识，按协议划分，再仅在训练集拟合预处理；Diabetes 增加患者级划分对照。修复后重跑并比较旧结果，不能直接将历史 JSON 当作修复后结论。

## 方法与实验层面的优化

**扰动应反映输入约束。** 当前 Gaussian 扰动独立作用于全部数值列；benchmark 的 one-hot 列在 LIME 中也按连续变量处理，可能产生无效类别组合。逐列 median ablation 同样不保持关联结构。建议先为现有二分类表格范围增加特征类型和约束元数据，再比较独立扰动、成组类别移除及有效域扰动的结果。此处是有效性风险，尚未量化其对当前数值的影响。

**敏感度应说明单位与估计预算。** 标准化的是输入邻域，输出归因差仍有单位；回归目标放大后固定阈值会改变结论。App 只评估一个样本、10 个扰动，真实 benchmark 使用 6 个扰动，结果是采样到的最大值，不是已找到真实 worst case。应同时保留原始值、明确单位、预算及重复估计，不应将很小的单次采样结果当作鲁棒保证。

**平均值需要有效样本数与分布。** 部分聚合使用 nanmean，但报告缺少“有效 n / 总 n”。真实 benchmark 每个模型/seed 仅解释 4 个样本，稳定性和敏感度只测第一个样本；目前不足以代表整体数据。应保存逐样本、逐 seed 原始结果，增加分位数与按实验独立单位构造的不确定性区间，避免把同一模型下多次测量当作完全独立证据。

**子群定义需要可解释。** 上传流程选择标准差最大的特征，结果依赖量纲；三等分可能因重复值退化成一两个群体。flip rate 还依赖哪个标签排在第一。应允许指定分组列，展示样本数、切点、参考群体；单群体标不适用。若需要对称统计，应另外定义 pairwise overlap，而非悄悄改变现有指标。

**文章需收紧超出数据的主张。** 文章保留“两个类别错误几乎所有工具都会犯”“大部分分歧是类别错误”等广泛表述，但自有示例 rank 仅从 0.74 到 0.75。应限定为本实验观察，并移除“子群差异即伪影”的推断。图生成器 `rho*x0 + sqrt(1-rho²)*N(0,0.35²)` 的 rho 不是 Pearson 相关：rho=0.85 时理论相关约 0.977，而正文写约 0.85。应修正生成公式或直接报告经验相关，再重生成图和数字。

## 工程和使用体验的优化

- 抽取一个库级分析入口与配置对象，供 App、demo、benchmark 共用。目前三处组合指标流程、预算和聚合方式容易漂移；benchmark 还复制了一份阈值字典。
- 复用构造好的 Tree/Linear explainer；批量执行 ablation 和随机移除预测。当前敏感度每个扰动重新构造 explainer，逐特征移除也逐次 predict。先记录阶段耗时与预测调用数，再改动，要求相同 seed 下结果保持在规定容差内。
- 上传流程使用“运行分析”按钮/表单，将昂贵计算结果留在会话内。现在没有与 synthetic 相同的缓存，选择展示实例等 rerun 也会重新跑完整流程。应限制解释行数、分组评估预算和特征数，并展示进度。
- 输入检查涵盖 NaN/Inf、常数列、空数据、错误形状、非法 task/model、n_runs<2、k=1、k>=d；对不支持的模型给出明确错误，不能仅凭 feature_importances_ 推断 TreeSHAP 一定支持。
- 报告增加 model 参数、数据/样本标识或安全摘要、依赖版本、解释器配置、实际背景、metric 状态、每项覆盖范围和 schema_version。当前 context 有数量和 seed，但不足以独立复现结果。
- 对类别任务除 accuracy 外报告类别分布及适当的预测性能指标，明确解释质量和模型预测质量的区别。上传时被丢弃的类别变量目前有审计信息，这是优点，但真实任务的结果范围应同步显示。
- 为实验提供可复现依赖约束文件；保持库安装依赖的合理范围。CI 补充采样型解释器回归、App 状态流程测试、fresh wheel import smoke test。当前 package job 只 build/twine check，不验证新环境安装运行。
- 文档收敛为“快速运行—完整分析—指标适用性—实验复现”路径；README、文章、demo 数字从保存的结果生成或校验，减少手工同步。

## 推荐项目方向

短期将项目定位为“可审计的表格解释诊断工具”：明确每个解释对应的模型输出、背景、扰动与预算，并让失败、缺失和方法差异各自可见。中期研究可以围绕“哪些诊断会误报/漏报，以及这种边界如何随背景、量纲、模型和预算变化”展开；仓库中的负结果已经提供了起点，但论文贡献仍需进一步文献查新和独立实验支持。

当前优势是完整的演示闭环和对计量细节的重视；当前短板是同一套严谨要求尚未完全贯彻到随机性、背景、边界情形和总体判定。优先把这四处做实，比继续堆叠功能更能提升项目价值。
